# DEADVERSE — سایت + پنل ادمین + بک‌اند رایگان

سایت فارسی/انگلیسی ددورس (کمیک، مقاله، فیلم، شخصیت، تیم) با پنل ادمین واقعی.
فرانت‌اند همان HTML قبلی است، فقط از `localStorage` به API وصل شده.

**پشته (همه روی پلن رایگان):**

| بخش | سرویس | هزینه |
|---|---|---|
| صفحه‌ی سایت و پنل | GitHub Pages (`nitson-games.github.io/deadverse`) | رایگان |
| API | Vercel (Node serverless) | رایگان (Hobby) |
| دیتابیس | Neon PostgreSQL | رایگان |
| تصاویر | همان Neon (جدول `media` از نوع `bytea`) — بدون سرویس ثالث | رایگان |

---

## ۱. ساخت دیتابیس روی Neon

**راه اول (سریع‌ترین، از CLI ورسِل — چیزی که واقعاً استفاده شد):**

```bash
npx vercel link --project deadverse --yes
npx vercel integration add neon     # دیتابیس Free می‌سازد و DATABASE_URL را به env تزریق می‌کند
npx vercel env pull .env.local      # برای اجرای محلی: همان رشته را روی دیسک می‌آورد
```

`integration add neon` این متغیرها را برای Production/Preview/Development می‌سازد: `DATABASE_URL` (pooled)، `DATABASE_URL_UNPOOLED`، `POSTGRES_*`، `PG*`. برای این پروژه فقط `DATABASE_URL` مصرف می‌شود. مقدارش را در `.env` محلی هم بگذار تا `npm run db:setup` از همان‌جا وصل شود.

**راه دوم (کنسول Neon، دستی):**

1. وارد [neon.tech](https://neon.tech) شو → **New Project** → نام `deadverse` → Region نزدیک خودت → Create.
2. از **Connect** (یا کارت Connection string) سوییچ **Connection pooling** را روشن کن؛ به رشته‌ای نیاز داری که نام endpointش با `-pooler` تمام می‌شود:

```
postgresql://user:****@ep-xxxx-pooler.<region>.aws.neon.tech/neondb?sslmode=require
```

> حتماً **pooled** (همان `-pooler`) باشد. روی Vercel هر instance یک اتصال جدید باز می‌کند و بدون pooler از سقف اتصال پلن رایگان رد می‌شوی.

3. `?sslmode=require` در URL باشد. خود سرور هم `rejectUnauthorized: true` را ست می‌کند و `sslmode` را از رشته حذف می‌کند تا رفتار TLS با تغییر نسخه‌ی `pg` عوض نشود (در `server/db.js`).

## ۲. تصاویر: روی همان Neon (بدون سرویس ثالث)

هیچ اکانت دیگری لازم نیست. عکس‌ها به‌صورت بایت در جدول `media` همان دیتابیس Neon ذخیره می‌شوند و API خودش آن‌ها را سرو می‌کند:

- آپلود: `POST /api/admin/media` با بدنه‌ی raw (فایل خام) → پاسخ `{ id, url: "/api/media/<id>", bytes }`.
- نمایش: `GET /api/media/<id>` با `Content-Type` واقعی و دو هدر کش جدا:
  - `Cache-Control: public, max-age=31536000, immutable` → مرورگر یک سال نگه می‌دارد (هر آپلود یک id تازه می‌گیرد، پس تصویر تکراری هیچ‌وقت عوض نمی‌شود و نسخه‌ی کهنه به کاربر نمی‌رسد).
  - `Vercel-CDN-Cache-Control: public, s-maxage=3600` → کش لبه‌ی Vercel فقط یک ساعت. این عمداً کوتاه است: وقتی آیتمی حذف می‌شود بایت‌هایش از دیتابیس می‌رود، اما اگر لبه یک سال نگهش داشت، آن تصویر یتیم تا یک سال روی دامنه‌ی خودت سرو می‌شد.
- نوع فایل از **بایت‌های اول** تشخیص داده می‌شود (JPEG/PNG/GIF/WebP)؛ هر چیز دیگری `400` می‌گیرد، پس کسی نمی‌تواند HTML یا اسکریپت از دامنه‌ی خودت سرو کند.
- سقف هر فایل ۴ مگابایت است (`MAX_MEDIA_BYTES` در `server/media.js`).
- مرورگر قبل از آپلود تصویر را تا ۱۶۰۰ پیکسل کوچک و WebP/JPEG فشرده می‌کند، برای همین یک پوستر معمولی ۱۰۰–۳۰۰ کیلوبایت می‌شود.
- در دیتابیس فقط مسیر `/api/media/<id>` ذخیره می‌شود، نه آدرس کامل — یعنی اگر یک‌روز دامنه یا نام پروژه‌ی Vercel عوض شود، هیچ تصویری نمی‌شکند (سایت و پنل مسیر را با `apiBase` در `config.js` می‌سازند).
- با حذف یا عوض‌کردن تصویر، بایت‌های قبلی از جدول `media` پاک می‌شوند؛ «بازنشانی همه داده‌ها» هم همه‌ی تصویرها را پاک می‌کند. بعد از حذف، نسخه‌ی داخل کش لبه هم حداکثر تا یک ساعت از بین می‌رود (بعد از آن `404` برمی‌گردد) — آدرس تصویر تصادفی است و جایی در سایت به آن لینک نمی‌شود.

بودجه‌ی پلن رایگان Neon حدود ۵۱۲ مگابایت ذخیره‌سازی است؛ با تصاویر فشرده‌شده این یعنی چند صد پوستر. شمارش و حجم در بخش «پشتیبان‌گیری» پنل نمایش داده می‌شود.

## ۳. اجرای محلی

```bash
git clone https://github.com/nitson-games/deadverse.git
cd deadverse
npm install
cp .env.example .env       # ویندوز:  copy .env.example .env
```

`.env` را پر کن (توضیح هر متغیر داخل خودش هست):

| متغیر | مقدار |
|---|---|
| `DATABASE_URL` | رشته‌ی pooled از Neon |
| `JWT_SECRET` | ۶۴ کاراکتر تصادفی ← `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `JWT_EXPIRES_IN` | `12h` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_DISPLAY_NAME` | ادمین اولیه؛ اگر رمز را خالی بگذاری خودکار ساخته و **چاپ** می‌شود |
| `ALLOWED_ORIGINS` | `https://nitson-games.github.io,http://localhost:5500,http://127.0.0.1:3000` |

از نسخه‌ی فعلی هیچ متغیر دیگری لازم نیست: تصاویر در همان `DATABASE_URL` ذخیره می‌شوند.

ساخت جداول + ادمین + داده‌های نمونه:

```bash
npm run db:setup
```

این اسکرپیت idempotent است: اگر ادمین یا رکوردی وجود داشته باشد، دست نمی‌زند. اگر `ADMIN_PASSWORD` خالی بوده، رمز تصادفی را **همان لحظه** کپی کن.

سرور محلی و تست:

```bash
npm run dev        # http://127.0.0.1:3000/api/health
npm test           # ۹۳ تست لایه‌ی HTTP + تست config.js (بدون دیتابیس)
npm run verify     # ۴۷ بررسی کامل روی دیتابیس واقعی (SQL، قیدها، CRUD، بکاپ)
```

بعد از `npm run dev` در ترمینال سه آدرس چاپ می‌شود؛ **فقط همین آدرس‌ها** را باز کن:

| آدرس | چیست |
|---|---|
| `http://127.0.0.1:3000/` | سایت لوکال |
| `http://127.0.0.1:3000/admin` | پنل ادمین لوکال |
| `http://127.0.0.1:3000/api/health` | خود API |

`config.js` روی این آدرس‌ها خودکار API لوکال را انتخاب می‌کند. فایلی را با `file://` یا Live Server (پورت ۵۵۰۰) باز نکن: آن حالت همان صفحه را به API وصل می‌کند ولی آدرس `/admin` را ندارد و گیج‌کننده می‌شود.

سرور لوکال عمداً **فقط چند فایل نام‌برده** را سرو می‌کند (`server/pages.js`: `index.html` در `/`، `admin.html` در `/admin`، `config.js`، `favicon.svg`، `og-cover.jpg`). هیچ پوشه‌ای لیست نمی‌شود و `express.static` استفاده نشده، پس `/.env`، `/server/…` و `/node_modules/…` همان‌جا ۴۰۴ می‌دهند — این را `npm run verify` هم چک می‌کند. نسخه‌ی دیپلوی‌شده هم **همین لیست** را منتشر می‌کند (`npm run build` فایل‌های `server/pages.js` را به `public/` می‌کپی می‌کند و `/admin` با rewrite به `admin.html` می‌رسد)، پس لوکال و زنده یک رفتار و یک مجموعه‌صفحه دارند.

## ۴. دیپلوی روی Vercel

پروژه‌ی Vercel به ریپوی گیت‌هاب `nitson-games/deadverse` متصل است: **هر `git push` روی `main` یک build جدید می‌سازد و جای نسخه‌ی قبلی را می‌گیرد** — کاری روی داشبورد نداری. آدرس اصلی سایت `https://www.deadverse.ir` است (دامنه‌ی اختصاصی؛ `deadverse.ir` بدون www با ۳۰۸ به `www` می‌رسد) و پنل: `https://www.deadverse.ir/admin`. آدرس `deadverse.vercel.app` هم هنوز بالا است و همان نسخه را سرو می‌کند. بعد از پوش چند لحظه صبر کن و بعد تأیید کن:

```bash
curl -s https://www.deadverse.ir/api/health
```

اگر نسخه‌ی تازه بالا نیامد، در داشبورد → Projects → Deployments لاگ build را بخوان (معمولاً خطای `runtime` یا یک متغیر Environment Variables جاافتاده).

**اگر روزی از صفر پروژه‌ی دیگری بسازی:** Import ریپو → Framework: **Other**، Build Command: `npm run build` و Output Directory: `public` (هر دو در `vercel.json` نوشته شده، پس داشبورد خودشان را پر می‌کند) — هر مسیر `/api/*` با همان `vercel.json` به تابع می‌رسد؛ ریپو باید `api/`، `server/`، `config.js`، `vercel.json` و `package.json` را داشته باشد. آدرس production با `POST /v9/projects/<id>/domains` روی API ورسل به هر ساب‌دامنه‌ی آزاد `*.vercel.app` وصل می‌شود (کاری که `deadverse.vercel.app` انجام داد؛ دامنه‌ی بلندتر حالا ۳۰۸ به آن می‌دهد).

نکته‌هایی که موقع دیپلوی این پروژه به آن بر خوردیم:
- در `vercel.json` **نویس `"runtime": "nodejs20.x"` ممنوع**؛ build با خطای `Function Runtimes must have a valid version` می‌میرد. نسخه‌ی Node را Vercel انتخاب می‌کند (و `engines.node` در `package.json` راهنمای آن است). `memory` هم با صورت‌حساب Fluid Compute نادیده گرفته می‌شود.
- `.vercelignore` جلوی آپلود `.env*`، `tests/` و پوشه‌های ابزار را می‌گیرد. بعد از دیپلوی چک کن: `curl -I https://www.deadverse.ir/.env` باید **۴۰۴** بدهد.
- ریشه‌ی استاتیک دیپلوی **`public/` است، نه کل ریپو**. `outputDirectory: "."` باعث می‌شد `/server/app.js` و `/server/routes.js` مستقیم دانلود شوند (کد منبع لو می‌رفت؛ راز نبود، چون رمزها در Environment Variable هاست). `npm run build` فقط فایل‌های همان لیست `server/pages.js` را در `public/` می‌گذارد، پس لوکال و پروداکشن یک مجموعه‌صفحه دارند و `npm run verify` هم `/server/app.js` و یک مسیر ساختگی را بین پاسخ‌های ۴۰۴ چک می‌کند.
- پوشه‌ی خروجی که `index.html` دارد، در ورسل هر مسیرِ نبوده را با همان `index.html` و وضعیت **۲۰۰** جواب می‌دهد (حالت SPA) و این هم باگ را از لاگ و هم از `verify` پنهان می‌کند. `404.html` فرقی نمی‌کند؛ کاری که جواب داد rewrite آخر `vercel.json` است: `"/(.*)" → /api/index`. چون فایل‌های واقعی قبل از rewriteها بررسی می‌شوند، صفحه‌ها copy خودشان را می‌گیرند و فقط مسیرهای ساختگی به تابع می‌روند و **۴۰۴** واقعی می‌گیرند.
- «Deployment Protection» روی پروژه روشن است ولی فقط **preview URL**ها را قفل می‌کند؛ آدرس production برای بازدیدکننده‌ی ناشناس باز است (با `curl -i https://www.deadverse.ir/api/health` تأییدشده).

متغیرهای لازم روی Vercel (محیط Production):

| متغیر | از کجا |
|---|---|
| `DATABASE_URL` | خودش با `vercel integration add neon` تزریق می‌شود |
| `JWT_SECRET` | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `ALLOWED_ORIGINS` | فقط برای مبدأ **خارج از** خودِ سایت لازم است (مثل `https://nitson-games.github.io`). سایت و API روی یک دامنه‌اند، پس `deadverse.ir` نیازی به اینجا ندارد |

تصاویر هم با همان `DATABASE_URL` می‌روند؛ متغیر سرویس ثالث دیگری روی Vercel لازم نیست.

`ADMIN_USERNAME` / `ADMIN_PASSWORD` روی Vercel **لازم نیست** — فقط `npm run db:setup` روی ماشین خودت آن‌ها را می‌خواند و بعد از آن رمز به‌صورت bcrypt در دیتابیس است. آن‌ها را در داشبورد Vercel نگذار.

بعد از دیپلوی، از همان ماشین تست راه دور:

```bash
npm run verify -- https://www.deadverse.ir
```

هر رکوردی که `verify` می‌سازد (کمیک، مقاله، پیام، مشترک خبرنامه، تصویر) در پایان همان اجرا از طریق endpoint های واقعیِ ادمین حذف می‌شود، پس دیتابیس پس از تست تمیز می‌ماند.

## ۵. آدرس API در `config.js`

سایت و API با هم دیپلوی می‌شوند، پس `config.js` همیشه `/api` **هم‌ریشه** را انتخاب می‌کند: هر دامنه‌ای که صفحه از آن سرو می‌شود (`deadverse.ir`، `www`، `*.vercel.app`، preview ها) به `/api` خودش حرف می‌زند. یعنی نه `API_BASE` در کد هست، نه CORS، نه ردیفی در Vercel — یک دامنه‌ی جدید را وصل می‌کنی و سایت بدون دیپلوی دوباره کار می‌کند.

قبلاً یک `API_BASE` مطلق (`https://deadverse.vercel.app/api`) در این فایل بود؛ همان چیز باعث شد با اضافه‌شدن `deadverse.ir` بنر «اتصال به سرور برقرار نشد» بالای سایت روشن شود: دامنه‌ی اختصاصی از دامنه‌ی ورسل CORS نمی‌گیرد و درخواست‌ها در مرورگر رد می‌شدند. آن متغیر حذف شده.

قاعده انتخاب آدرس در `resolve()` این است (`tests/config.test.js` همان را با `vm` و یک `window` ساختگی تست می‌کند):

- `?api=...` در URL → همیشه اولویت اول (برای تست موقت؛ اگر کامل باشد محیط `external` گزارش می‌شود).
- `file://`، `localhost`، `127.0.0.1` → `http://127.0.0.1:3000/api`.
- بقیه → `/api` هم‌ریشه.

پنل ادمین: `https://www.deadverse.ir/admin` — آدرس تمیز، بدون `.html` (rewrite در `vercel.json` به فایل `admin.html`). آدرس قدیمی `/adminpanel.html` دیگر فایلی نیست و فقط به `/admin` ریدایرکت می‌شود تا بوکمارک‌های قبلی نشکنند. صفحه هیچ لینکی به پنل ندارد و با `noindex` از ایندکس گوگل بیرون می‌ماند؛ برای ورود فقط خود `/admin` را تایپ کن.

## ۶. لایه‌ی اتصال و امنیت

`request()` در `config.js` تنها راه رفتن به API است: متد، هدر `Authorization: Bearer` از `sessionStorage` و `Content-Type` را می‌گذارد و پاسخ خطا را به آبجکتی با `status`، `code` و `details` (خطاهای فیلدی) تبدیل می‌کند؛ `fieldErrors()` همان `details` را به نقشه‌ی فیلد تبدیل می‌کند تا پنل زیر هر اینپوت پیام بگذارد. هیچ `eval` و `innerHTML` با داده‌ی خام کاربر نداریم؛ متن‌های خروجی با `esc()` escape می‌شوند.

پنل ادمین یک تابع `call()` دارد که همه‌ی درخواست‌ها از آن رد می‌شوند، پس ۴۰۱ همیشه به صفحه‌ی ورود برمی‌گرداند و ۴۰۳/۵۰۰ فقط toast می‌شوند.

خطاهای اعتبارسنجی با `status: 400` و آرایه‌ی `details: [{field, message}]` برمی‌گردند؛ `DEADVERSE.fieldErrors()` همان را به نقشه‌ی فیلد تبدیل می‌کند تا پیام زیر input مربوطه بنشیند. مقادیر پویا در هر دو صفحه با `esc()` escape می‌شوند و `eval` یا `new Function` در پروژه نیست. برای سقف اتصال Neon هم `DB_POOL_MAX` (پیش‌فرض ۱ در هر instance) در دسترس است.

## ۷. استفاده‌ی روزانه

- **ورود**: آدرس پنل `https://www.deadverse.ir/admin` است (روی سایت هیچ لینکی به آن نیست، صفحه هم `noindex` است). صفحه‌ی ورود هیچ اشاره‌ای به رمز یا نام کاربری پیش‌فرض نمی‌دهد. رمز ثابت `admin/deadverse` دیگر وجود ندارد. JWT با `token_version` است؛ با تغییر رمز، همه‌ی سشن‌های قبلی باطل می‌شود. ورود پشت rate-limit است (چند تلاش غلط → ۴۲۹ موقت).
- **رمز ادمین**: `ADMIN_USERNAME` / `ADMIN_PASSWORD` فقط در `npm run db:setup` (و فقط وقتی جدول خالی است) خوانده می‌شود و بعد از bcrypt در دیتابیس ذخیره می‌شود. این دو فقط در `.env` محلی لازم‌اند؛ روی Vercel جایی ندارند (سرور به آن‌ها نیازی ندارد). بعد از اولین ورود می‌توانی از بخش «رمز عبور» عوضش کنی.
- **ادمین‌ها و دسترسی‌ها**: بخش «👤 ادمین‌ها» (فقط با دسترسی `admins`) حساب جدید می‌سازد: نام نمایشی، نام کاربری، رمز و تیک‌های دسترسی. هشت دسترسی این‌ها هستند:
  `content` (کمیک/مقاله/فیلم/شخصیت + آپلود تصویر)، `team` (بخش تیم سایت — تیک جدا دارد، به‌خاطر اینکه نویسنده‌ی محتوا نتواند آدم‌های تیم را عوض کند)، `messages`، `newsletter`، `members` (خواننده‌ها)، `site`، `backup` (Export/Import/Reset)، `admins`.
  - هر درخواست سمت سرور چک می‌شود؛ بدون دسترسی → `403` با پیام «دسترسی «x» برای حساب شما فعال نیست».
  - عوض‌کردن دسترسی/فعال‌بودن یک حساب، `token_version` آن را بالا می‌برد و نشست‌هایش بی‌اثر می‌شود.
  - حساب خودش نمی‌تواند دسترسی‌اش را کم کند، خودش را غیرفعال یا حذف کند — پس قفل‌شدن پنل پیش نمی‌آید. برای تغییر این موارد روی حساب خودت، باید یک ادمینِ دیگر با دسترسی `admins` وارد شود.
  - نام کاربری بعد از ساخت تغییر نمی‌کند؛ اگر لازم شد، حساب را حذف و دوباره بساز.
  - «غیرفعال» رکورد را پاک نمی‌کند؛ فقط ورود و نشست‌های آن حساب قطع می‌شود.
- **محتوا**: افزودن/ویرایش/حذف کمیک، مقاله، فیلم، شخصیت، تیم. ترتیب نمایش = ترتیبی که در لیست ذخیره می‌شود.
  - **هر رکورد صفحه‌ی خودش را دارد**: `/comics/<slug>`، `/articles/<slug>`، `/movies/<slug>`، `/characters/<slug>` (همه با یک فایل `item.html`، رکورد از آدرس خوانده می‌شود). اسلاگ هنگام ساخت خودکار از تیتر انگلیسی ساخته می‌شود (اگر تکراری باشد `-2` می‌گیرد) و اگر بخواهی دستی نوشتنش همان ذخیره می‌شود؛ خالی بگذاری یعنی «خودکار». **عوض‌کردن تیتر، آدرس صفحه را عوض نمی‌کند** تا لینک‌های اشتراک‌گذاری‌شده نشکنند — فقط وقتی خودت اسلاگ را بنویسی آدرس عوض می‌شود. در هر ردیف پنل دو دکمه هست: ✎ ویرایش و «🔗 صفحه» (همان آدرس تمیز). `/comics/<id>` هم کار می‌کند، برای پیش‌نمایش رکوردی که هنوز اسلاگش را ندیده‌ای.
  - **مقاله = چیدمان بلوکی**: در فرم مقاله، «متن کامل» دو تا textarea دیگر نیستند؛ یک ویرایشگر **چیدمان** هست که هر پاراگراف یک بلوک است و تصویر را می‌توانی *هر جایی* بین پاراگراف‌ها بگذاری (نه فقط اول و آخر). با دستگیره‌ی ⠿ بکش‌ورها کن، یا ↑↓ (روی موبایل فقط دکمه، چون کشیدنی وجود ندارد)، با «＋ پاراگراف» و «🖼 تصویر» بلوک تازه اضافه کن، و زیر هر پاراگراف «＋ تصویر اینجا» همان‌جا عکس می‌چیند. تب «متن ساده» همان چیدمان را به شکل خام نشان می‌دهد. در فهرست مقالات، `🖼 N` تعداد واقعی تصویرهای بدنه است.
    - روی سیم، همان دو ستون `body_fa` / `body_en` می‌مانند و هر تصویر یک خط خودش است: `[[img:/api/media/md_…]]` یا `[[img:https://…]]`. اگر پاراگرافی لازم دارد آن نشانه را *نمایش* دهد، با `\` اول خط فرار می‌کند. نشانه‌ای که آدرسش بارگذاری نشود (مثلاً `javascript:`) در پنل و در API با خطای همان فیلد رد می‌شود، و هر مقاله حداکثر ۲۴ تصویر داخل متن دارد.
    - مقاله‌های قدیمی که هنوز تصویرهایشان در دو اسلات `midImage` / `lateImage` است، درست مثل قبل نمایش داده می‌شوند؛ به‌محض اینکه در چیدمان یک تصویر بگذاری، اسلات‌های قدیمی کنار همان تصویر می‌چینند و دیگر روی صفحه تکراری نمی‌آید. بایت‌های تصویرِ داخل متن هم مثل اسلات‌ها آزاد می‌شوند: تا وقتی نشانه‌اش در بدنه هست، حذف نمی‌شود.
  - **کمیک = یک توضیح + لینک دانلود**: فرم کمیک فقط «توضیحات (فارسی/انگلیسی)» را دارد (فیلد متن بلند حذف شده، همان‌طور که روی صفحه‌ی کمیک هم نمایش داده نمی‌شود) و یک «لینک دانلود کمیک» (`downloadUrl`) که مثل لینک فیلم فقط با `http(s)://` ذخیره می‌شود و روی صفحه‌ی کمیک دکمه‌ی سبز «⬇ لینک دانلود کمیک» می‌سازد.
  - فیلم‌ها یک فیلد اضافه دارند: **«لینک مشاهده»** (`watchUrl`) که فقط با `https://` یا `http://` ذخیره می‌شود (هر چیز دیگری مثل `javascript:` با خطای همان فیلد رد می‌شود) و روی صفحه‌ی فیلم به‌صورت دکمه‌ی «▶ لینک مشاهده فیلم» باز می‌شود.
  - متن بلند (`body_fa` / `body_en`) فقط از صفحه‌ی خود رکورد می‌آید و در `/api/bootstrap` نیست؛ برای شخصیت و فیلم همان textareaهای معمولی‌اند.
  - پاسخ `/api/bootstrap` عمداً ۲۰ ثانیه کش می‌شود (`Cache-Control: public, max-age=20`)؛ بعد از ذخیره در پنل، سایت حداکثر تا ۲۰ ثانیه نسخه‌ی قبلی را نشان می‌دهد. برای دیدن فوری، صفحه را با `Ctrl+Shift+R` باز کن.
- **خواننده‌ها (عضویت برای مقالات)**: صفحه‌ی هر مقاله فقط برای عضو باز می‌شود؛ بقیه‌ی سایت عمومی است. بازدیدکننده از بنر «ورود» بالای سایت (`?signin=1`) یا خود صفحه‌ی مقاله ثبت‌نام می‌کند: نام کاربری (حروف کوچک، `.` `-` `_`)، رمز ≥ ۸ کاراکتر، نمایشی و ایمیل اختیاری + سوال راستی‌آزمایی. توکن خواننده در `localStorage` است (`dv_member_token`) و با توکن ادمین تفاوت `kind` دارد، پس هیچ‌کدام جای دیگری را باز نمی‌کند. رمز را خودت عوض یا بازنشانی کنی → نشست‌های آن حساب باطل می‌شود.
  - بخش «🧑‍🚀 خواننده‌ها» در پنل (با دسترسی `members`) فهرست، جستجو، ساخت دستی حساب، نمایش آخرین بازدید، غیر/فعال‌کردن، بازنشانی رمز و حذف را دارد. جمع کل در داشبورد از `stats.members` (`{total, active, recent}`) می‌آید.
  - «غیرفعال» یعنی همان لحظه از صفحه‌ای که خواننده باز دارد می‌افتد بیرون (`token_version` بالا می‌رود)؛ رکوردش پاک نمی‌شود.
  - خود خواننده هم از بخش «حساب من» می‌تواند رمزش را عوض کند یا کل حساب را حذف کند (`DELETE /api/member/account`).
- **ضد‌اسپم فرم تماس و عضویت**: چهار لایه، همه سمت سرور:
  1. **دام‌عسلی** (`website`) — یک فیلد بیرون از صفحه که ربات پر می‌کند؛ اگر پر باشد، پاسخ `201` داده می‌شود ولی **هیچ چیز ذخیره نمی‌شود** (تا ربات نفهمیده باشد گرفته شده و فیلد را عوض کند).
  2. **سوال حسابی امضاشده** — `GET /api/challenge` دو عدد و یک عملیات می‌دهد و توکنی که HMAC روی همان اعداد + هش IP + زمان است (۱۵ دقیقه عمر، مقایسه با `timingSafeEqual`). چون IP داخل امضا است، توکنی که یک ماشین گرفته روی ماشین دیگر کار نمی‌کند و خود مرورگر هم نمی‌تواند آن را بسازد. اعداد فارسی، عربی و لاتین همه پذیرفته می‌شوند.
  3. **Turnstile** — اگر `TURNSTILE_SITEKEY` و `TURNSTILE_SECRET` را در Vercel بگذاری، به‌جای سوال، ویجت استفاده می‌شود و سوال اصلاً نمایش داده نمی‌شود (تا آن‌ها را نگذاشته‌ای، همان سوال حسابی فعال است).
  4. **سقف فرستادن**: هر ایمیل تا `CONTACT_COOLDOWN_MINUTES` (پیش‌فرض ۳۰ دقیقه) نمی‌تواند دوباره پیام بدهد (۴۲۹) و متن دقیقاً تکراری رد می‌شود؛ هر IP هم حداکثر ۳ پیام در ۱۰ دقیقه.
  - هر کدام از این رد‌ها پیام فارسی دارد و فرم همان سوال تازه را می‌دهد. برای تست: `npm run verify -- https://www.deadverse.ir` (بخش «فرم‌های بازدیدکننده»).
- **تصویر**: در پنل فایل را انتخاب می‌کنی؛ مرورگر آن را تا ۱۶۰۰ پیکسل کوچک و فشرده می‌کند و بایت‌ها در دیتابیس ذخیره می‌شوند. در رکورد فقط مسیر `/api/media/<id>` ذخیره می‌شود. اگر ویرایش کنی و دوباره آپلود نکنی، همان تصویر قبلی حفظ می‌شود؛ وقتی تصویر عوض یا آیتم حذف می‌شود، بایت‌های قبلی از جدول `media` پاک می‌روند تا فضا آزاد بماند.
- **تنظیمات سایت**: متن هیرو، درباره و دکمه‌ها در دو زبان؛ دقیقاً همان‌جا که در سایت نمایش داده می‌شود. گروه «لینک‌های شبکه‌های اجتماعی» هم همین‌جا است: ایکس، اینستاگرام، یوتیوب و دیسکورد. هر کدام که خالی بماند، آیکونش از فوتر حذف می‌شود (آیکون مرده روی سایت نمی‌ماند) و آدرس باید با `https://` شروع شود.
- **اشتراک‌گذاری در شبکه‌ها**: `favicon.svg` و `og-cover.jpg` در ریشه‌ی ریپو هستند و تگ‌های `og:`/`twitter:`/`canonical` در `index.html` و `item.html` آن‌ها را با آدرس کامل `https://www.deadverse.ir/...` نشان می‌دهند. این آدرس‌ها فقط برای ربات شبکه‌های اجتماعی‌اند (سایت خودشان هم‌ریشه کار می‌کند)، پس اگر روزی دامنه عوض کردی تنها جایی که باید عوض شود همین بلوک متا است — `config.js` و تنظیمات Vercel دست‌نخورده می‌مانند.
- **پیام‌ها / خبرنامه**: اینباکس با خوانده‌نشده، خروجی CSV مشترکین. هر مشترک دکمه‌ی حذف دارد (`DELETE /api/admin/subscribers/:id`)؛ تا ایمیل‌های تستی در لیست نمانند.
- **پشتیبان**: Export یک JSON کامل (محتوا + پیام‌ها + تنظیمات) و Import همان فایل. Import کل دیتابیس را بازنشانی می‌کند — قبلش فایل را نگه دار. بایت‌های تصویر در این JSON نیستند (فقط مسیرشان ذخیره می‌شود و تا همان‌جا که دیتابیس پاک نشده کار می‌کند)؛ برای پشتیبان واقعی از کنسول Neon یک Snapshot بگیر.

- **موبایل**: چهار قاعده در CSS هست که اگر عوض‌شان کنی باگ برمی‌گردد؛ کنار هرکدام کامنت `why` گذاشته شده:
  - فونت همه‌ی input/textarea روی گوشی `1rem` است — iOS هر فیلدی که زیر ۱۶ پیکسل باشد را بزرگ می‌کند و دیگر برنمی‌گرداند، پس کل صفحه زوم می‌ماند.
  - ارتفاع‌ها `100dvh`/`100svh` هستند نه `100vh`، چون نوار آدرس مرورگر موبایل داخل `vh` حساب می‌شود و پایین صفحه زیر آن می‌رفت.
  - فیلد دام‌عسلی با `clip-path: inset(50%)` پنهان می‌شود، نه `left:-9999px`؛ با آن نسخه‌ی قبلی عرض کل سند تا ۱۰٬۳۶۱ پیکسل می‌رفت و صفحه روی گوشی افقی کشیده می‌شد.
  - `1fr` در گریدها `minmax(0, 1fr)` نوشته شده (فوتر، فرم خبرنامه) چون کفِ `1fr` برابر min-content آیتم است و یک `<input>` با `size=20` پیش‌فرض، خودش ۳۲۰ پیکسل عرض می‌خواهد.
  - تست این‌ها در مرورگر واقعی: اینپیج را در `<iframe width="320">` باز کن و `documentElement.scrollWidth` را بخوان؛ باید ≤ `innerWidth` باشد. (سرور لوکال `X-Frame-Options: DENY` می‌فرستد، پس برای این کار فایل‌ها را با یک استاتیک ساده سرو کن؛ روی پروداکشن CDN این هدر نیست.)
- **فونت‌ها**: `fonts.googleapis.com` با `media="print" onload="this.media='all'"` بارگذاری می‌شود تا درخواست کند یا بی‌پاسخِ فونت جلوی اولین نقاشی صفحه را نگیرد؛ بنر «DEADVERSE» هم با `load` پنهان می‌شود ولی یک ددلاین ۵ ثانیه‌ای هم دارد تا هیچ‌وقت پشت صفحه‌ی سیاه گیر نکند. اگر روزی خواستی از گوگل مستقل شوی، `Vazirmatn` و `Bebas Neue` را در پوشه‌ای داخل `public/` بگذار و `@font-face` بنویس — `npm run build` فعلاً فقط فایل‌های فهرست‌شده در `server/pages.js` را کپی می‌کند، پس باید اسم فایل‌ها را به همان فهرست اضافه کنی.

## ۸. رفع خطاها

| نشانه | علت / راه‌حل |
|---|---|
| پنل: «ارتباط با سرور برقرار نشد» | `API_BASE` اشتباه، یا `ALLOWED_ORIGINS` شامل آدرس Pages نیست. |
| ۴۰۱ بعد از دیپلوی مجدد | توکن در `sessionStorage` است؛ یک‌بار خارج شو و دوباره وارد شو. |
| `Missing required environment variables: DATABASE_URL, JWT_SECRET` در Vercel | متغیرها برای Environment = Production تیک نخورده‌اند؛ بعد از افزودن **Redeploy** کن. |
| آپلود تصویر `۴۰۰` «فقط JPEG، PNG، GIF یا WebP» | فایل واقعی این فرمت‌ها نیست — سرور نوع را از بایت‌های اول می‌خواند، نه از پسوند نام. |
| آپلود تصویر `۴۱۳` | خروجی فشرده‌سازی از ۴ مگابایت بیشتر است؛ ابعاد یا کیفیت را کم کن. |
| تصویر در سایت نمایش داده نمی‌شود ولی در پنل هست | `/api/media/…` هم‌ریشه‌ی خود صفحه است؛ اگر از مبدأ دیگری باز کرده‌ای (فایل محلی، GitHub Pages، پیش‌نمایش روی دامنه‌ی دیگر) آن مبدأ `/api` ندارد. با `?api=https://…/api` در URL تست کن. |
| تصویر حذف‌شده هنوز با آدرس مستقیم باز می‌شود | کپی داخل کش لبه‌ی Vercel است؛ تا یک ساعت خودش پاک می‌شود و تا آن موقع جایی به آن لینک نمی‌شود. مرورگر خودت ممکن است نسخه‌ی کش‌شده را نشان دهد — با `Ctrl+Shift+R` تست کن. |
| `npm run verify` می‌گوید «دیتابیس خالی است» | `npm run db:setup` اجرا نشده. |
| خطای connection / `too_many_connections` | URL بدون `-pooler` گذاشته شده. |
| سایت، داده‌ی نمونه‌ی قدیمی نشان می‌دهد + بنر «اتصال برقرار نیست» | API در دسترس نیست؛ fallback فعال شده. `curl -i <دامنه>/api/health` بزن: اگر ۴۰۴ داد دامنه به پروژه‌ی Vercel وصل نیست (یا دیپلوی بالا نیامده)، اگر ۲۰۰ داد ولی بنر هنوز هست نسخه‌ی قدیمیِ کش‌شده را باز می‌کنی (`Ctrl+Shift+R`). |
| دامنه‌ی جدید وصل کردی و همان بنر آمد | دامنه‌ی بدون www ممکن است با ۳۰۸ به `www` برود؛ هر دو را جدا با `curl -i` چک کن. از وقتی `config.js` هم‌ریشه است، خودِ بنر نباید برگردد — اگر برگشت یعنی `/api` روی آن دامنه سرویس نمی‌شود. |
| روی گوشی صفحه سیاه/«DEADVERSE» گیر کرده | بنر ورودی فقط با `load` پنهان می‌شود و یک ددلاین ۵ ثانیه‌ای هم دارد؛ اگر گیر کرد یعنی یک اسکریپت قبل از آن خطا داده (کنسول را چک کن). فونت هم دیگر بلاک‌کننده نیست. |
| روی گوشی صفحه افقی کشیده می‌شود | همیشه یک عنصر از عرض viewport بیرون زده: `documentElement.scrollWidth` را با `innerWidth` مقایسه کن و بعد فرزندِ `body` را که `scrollWidth > clientWidth` دارد پیدا کن. `body{overflow-x:hidden}` این را پنهان می‌کند، درست نمی‌کند. |
| موقع تایپ کردن، صفحه زوم می‌شود و برنمی‌گردد | فونت آن input زیر ۱۶ پیکسل است؛ در بلوک `@media (max-width: 768px)` بالای آن را `1rem` کن. |
| در پنل پیام «دسترسی «x» برای حساب شما فعال نیست» | حساب تو آن دسترسی را ندارد؛ با یک ادمین که دسترسی `admins` دارد وارد شو و از بخش ادمین‌ها تیکش را فعال کن (بعد از تغییر دسترسی باید دوباره وارد شوی). |
| بخش «ادمین‌ها» در منو نیست | حساب جاری دسترسی `admins` ندارد. اگر همه‌ی حساب‌ها آن را ندارند، `npm run db:setup` دوباره اجرا نمی‌شود؛ از طریق SQL: `UPDATE admins SET permissions = '{content,messages,newsletter,site,backup,admins}' WHERE username = '...'`. |
| «ستون permissions در admins نیست» در `npm run verify` | `npm run db:setup` را بعد از کشیدن آخرین نسخه اجرا کن (ALTER روی جدول قدیمی لازم است). |
| چیزی در پنل ذخیره می‌کنی و سایت عوض نمی‌شود | یا بنر «اتصال برقرار نیست» بالای سایت روشن است (API در دسترس نیست)، یا آدرس بار مرورگر را چک کن: یک نمونه‌ی قدیمیِ فقط‌فرانت (بدون `/api`، با `login-hint` روی صفحه لاگین) که داده را در `localStorage` مرورگر می‌نوشت. آن پروژه پاک شده و `deadverse.ir` / `deadverse.vercel.app` حالا خودِ همین پروژه‌اند؛ نشانه‌ی نسخه‌ی درست: پنل روی `/admin` باز می‌شود و نوار کناری آدرس API و محیط (لوکال/زنده) را می‌نویسد. |
| پیام «زیادی تلاش کردید، کمی بعدتر دوباره امتحان کنید» (۴۲۹) | محافظ ورود است: هر IP حداکثر ۸ تلاش ورود در ۵ دقیقه. `npm run verify` هم چند ورود می‌زند، پس پشت سر هم اجرا نکن — سرور در پاسخ `Retry-After` ثانیه‌های باقی‌مانده را می‌گوید. |
| صفحه‌ی مقاله می‌گوید «برای خواندن این صفحه عضو شوید» | عمدی است: فقط مقالات پشت عضویت‌اند، بقیه‌ی سایت عمومی. با بنر ورود یا دکمه‌ی همان صفحه حساب ساخته می‌شود. اگر متنی هست که همه باید ببینند، در «توضیح کوتاه» بنویسش (توضیح کوتاه در فهرست عمومی می‌آید، متن کامل نه). |
| تیتر را عوض می‌کنی و آدرس صفحه عوض نمی‌شود | عمدی است: تا لینک‌های فرستاده‌شده نشکنند، اسلاگ ذخیره‌شده حفظ می‌شود. برای آدرس تازه، خودت اسلاگ را در فیلد «آدرس صفحه» بنویس (خالی = بدون تغییر). |
| «جواب سوال درست نبود یا وقتش تمام شده؛ دوباره بپرسید» | هر چالش ۱۵ دقیقه عمر دارد و فقط برای همان IP کار می‌کند؛ «سوال جدید» را بزن. اگر پیام اصلاً ارسال نمی‌شود ولی هیچ خطایی هم نمی‌بینی، فیلد پنهان `website` پر شده (دام‌عسلی) — درخواست بی‌صدا دور ریخته می‌شود. |
| پیامی که از فرم می‌فرستی ذخیره نمی‌شود و ۴۲۹ می‌گیری | همان ایمیل داخل `CONTACT_COOLDOWN_MINUTES` دقیقه فرصت دوباره ندارد؛ با ایمیل دیگر یا بعد از آن پنجره امتحان کن. |
| در پنل، بخش «خواننده‌ها» یا «تیم» در منو نیست | حساب جاری تیک آن بخش را ندارد (`members` و `team` جدا از `content`‌اند)؛ با یک ادمینِ دارای `admins` تیکش را فعال کن و دوباره وارد شو. |

## ۹. ساختار فایل‌ها

```
index.html            سایت عمومی + ورود/عضویت خواننده (API-driven)
item.html             یک صفحه برای هر رکورد: /comics|articles|movies|characters/<slug> (گیت مقاله، لینک مشاهده، انیمیشن)
admin.html            پنل ادمین (API-driven) — از طریق /admin باز می‌شود
favicon.svg           آیکون تب مرورگر
og-cover.jpg          تصویر اشتراک‌گذاری در شبکه‌های اجتماعی (1200×686)
config.js             client مشترک: آدرس API، fetch، توکن ادمین و توکن خواننده، آدرس صفحه، خطاهای فیلدی
api/index.js          ورودی serverless Vercel (Express app)
vercel.json           build → public/، rewrite /api/*، /admin، چهار پیشوند صفحه‌ی رکورد + ریدایرکت /adminpanel.html (بدون `runtime`؛ نسخه Node را Vercel انتخاب می‌کند)
.vercelignore         .env*، tests/ و پوشه‌های ابزار آپلود نمی‌شوند
server/
  app.js              Express + CORS + هدرهای امنیتی + error handler
  routes.js           همه‌ی endpointها
  repo.js             کوئری‌ها (repository pattern) + ساخت اسلاگ و آوانگاری فارسی
  db.js               pool Neon (ssl verify، پیش‌فرض ۱ اتصال به هر instance)
  schema.sql          جداول و قیدها
  validate.js         zod: کلاینت -> ستون‌های دیتابیس
  auth.js             JWT (دو kind: ادمین و خواننده) + bcrypt
  permissions.js      فهرست هشت دسترسی و برچسب فارسی هرکدام
  spam-guard.js       چالش حسابی امضاشده + راستی‌آزمایی Turnstile
  media.js            سقف حجم، تشخیص نوع از بایت‌ها، پالایش idهای ما
  ids.js              پیشوندهای id (cm_، ar_، mv_، mb_ و …) و ساختار id تصادفی
  pages.js            سرو /، /admin و صفحه‌ی هر رکورد در حالت لوکال — فقط فهرست نام‌های مشخص
  rate-limit.js       پنجره‌ی ثابت در حافظه
  migrate.js          npm run db:setup
  verify.js           npm run verify — ۴۷ بررسی روی دیتابیس واقعی
scripts/
  build-site.js       npm run build — کپی صفحه‌های فهرست‌شده در public/ (ریشه‌ی استاتیک دیپلوی)
tests/                ۸۶ تست HTTP با fake repo (بدون دیتابیس) — api/pages/reader/staff
                      + ۷ تست config.js که با یک `window` ساختگی ثابت می‌کنند آدرس API همیشه هم‌ریشه است
.env.example          الگوی متغیرها
```

**`ALLOWED_ORIGINS` را با `/` انتهایی ننویس** و `JWT_SECRET` را کامیت نکن — `.gitignore` فقط فایل‌های `.env*` را از git بیرون نگه می‌دارد، پس رمزها را هیچ‌وقت مستقیم داخل HTML یا `config.js` ننویس.
